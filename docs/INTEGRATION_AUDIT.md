## ثغرات أمان وُجدت وأُصلحت (migrations `20261018100000`–`130000`)

1. **تصعيد صلاحيات:** أي مستخدم مسجل كان يستطيع تنفيذ `UPDATE users SET role='admin'` على صفه (سياسات UPDATE بلا قيد أعمدة ومنح `UPDATE(role)`). أُزيلت السياسات وسُحب المنح، وبقي تعديل `full_name/email` فقط. **مثبت باختبار.**
2. **`crm_leads`:** سياسات `anon_full_access` و`auth_full_access` (`USING true`): أي حامل لمفتاح anon يقرأ ويكتب خط مبيعات الوكالة. استُبدلت بسياسة أدمن فقط. **مثبت باختبار.**
3. **`sales_blitz_leads`:** سياسة باسم «admin only» تنطبق فعليًا على كل الأدوار. أُصلحت. **مثبت باختبار.**
4. **`companies`:** مالك الشركة كان يستطيع تعديل `plan`/`message_limit`/حالة الاشتراك بنفسه. أُضيف trigger يمنع تغيير أعمدة الفوترة والملكية لغير الأدمن. **مثبت باختبار.**
5. الأدمن لم يكن يملك سياسة UPDATE على `companies`: تعديلات الواجهة كانت **تنجح ظاهريًا وتغيّر 0 صفوف**. أُضيفت السياسة، وصارت الواجهة تتحقق من عدد الصفوف.

الاختبار: `python scripts/test-db-isolation.py` (يعمل داخل BEGIN/ROLLBACK ولا يغيّر شيئًا): 41 فحصًا ناجحًا.
